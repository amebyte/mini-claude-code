THE ESSENCE · 本质

一、本质：模型产代码，harness 落盘

模型本身不直接操作文件系统，它只负责「说」；真正把代码写到磁盘的，是宿主程序里的工具函数。
01 · SAY
模型负责「说」
输出的是 tool_use 块，
而不是代码文件本身
02 · DO
harness 负责「做」
查表 → FileWriteTool.call()
→ 写入磁盘
03 · LOOK
模型负责「看」
tool_result 回传，
决定下一步
model → harness — 说与做的完整链路
// ① 模型负责「说」—— 输出结构化 tool_use { "name": "Write", "input": { "file_path": "src/App.vue", "content": "...代码..." } } // ② harness 负责「做」—— 查表 → FileWriteTool.call() mkdir(dirname(file_path), { recursive: true }) // 建目录 fs.writeFile(file_path, content) // 写文件 ← 落盘

THE KEY INSIGHT · 关键认知

四、关键认知：能力来自模型，落地来自工程

MODEL · 模型
「会写代码」的能力
来自 Claude 模型本身的推理与编码能力——它知道 Vue3 的 TodoList 该怎么组织、语法该怎么写。
HARNESS · 工程外壳
「能动手写」的落地
循环负责驱动、注册表负责分发、工具负责真实系统操作、tool_result负责反馈闭环。
Claude Code 不是「一个会写代码的程序」，而是「一个被赋予终端手脚、在循环里自主决策的模型」。
模型产代码 · harness 落盘 —— 这就是它写代码的全部秘密
AI 编程工具的能力边界在哪？
答案不在模型，而在工具——模型再聪明也只能「说」，真正「做」的是 harness 提供的工具；工具越多、越可靠，agent 能做的事就越多。理解了这一层，Cursor / Copilot / Claude Code 都不过是在这个骨架上做加减法。
