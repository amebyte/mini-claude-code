FUNCTION CALLING · TOOL SPEC
03 / 09

关键机制:Function Calling

调 API 时,先把「有哪些工具可用」提前告诉模型 —— 每个工具一份说明书

说明书三要素
name
名字
模型靠它点名要调哪个工具
description
作用
模型靠它判断「这个任务用不用得上」
parameters
参数
模型靠它知道「要传什么、传什么类型」
tools.json —— bash 工具说明书
{ "name": "bash", "description": "执行 shell 命令", "parameters": { "command": { "type": "string" } } }

模型看完说明书,才知道「有这么个工具、该怎么调」—— 说明书质量直接决定工具调用质量

Function Calling 的流程

模型不直接输出最终答案,而是先输出一个「调用请求」

FOUR STEPS
1
告诉模型有哪些工具
每个工具一份说明书:name / description / parameters
2
模型输出 tool_use
「我要调 bash,参数是 ls」—— 而不是直接给答案
3
客户端真正执行
我们替它跑 ls,把结果包成 tool_result 回喂
4
模型继续作答
看到结果后组织语言 —— 或发起下一次调用
