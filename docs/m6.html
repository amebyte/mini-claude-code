COMMAND EXECUTION FLOW
05 / 08

命令执行的具体流程

当用户在终端中输入一条命令后，系统会按以下步骤处理

01
判断是否包含路径
若命令显式给出文件路径（如 /usr/bin/ls 或 C:\tools\node.exe），则直接读取该路径下的可执行文件并运行——即绝对路径或相对路径执行。
02
区分内部命令与外部命令
未指定路径时，解析器先检查是否为内部命令（解释器自身内置的功能，如 Linux 的 cd、Windows 的 dir）。内部命令常驻内存，无需额外加载即可执行。
注意：ls 在大多数 Linux 发行版中属于外部命令（位于 /bin/ls），而非内部命令，此处需加以区分。
03
在 PATH 环境变量中查找
既非内部命令也未带路径时，解析器在 PATH 定义的目录列表中依次搜索匹配的可执行文件。日常配置软件时需设置 PATH，正是为了让系统能找到命令程序。
04
报错处理
若以上步骤均未找到匹配的可执行文件，命令解析器返回「命令未找到」的错误信息，如 bash: foo: command not found。
NODE.JS · CHILD_PROCESS
06 / 08

在 Node.js 中怎么执行命令？

内置 child_process 子进程模块——创建子进程，让 Node.js 执行其他程序或系统命令

核心区别：是否创建 Shell · 流式 or 缓冲 · 同步或异步

spawn
核心方法
SHELL不创建，直接执行指定程序
DATA流式（Stream）逐块返回输出
USE长时间运行 / 大量输出的命令
import { spawn } from 'node:child_process'; const child = spawn('ls', ['-lh', '/usr']); // 流式获取标准输出 child.stdout.on('data', (data) => { console.log(`stdout: ${data}`); }); // 进程结束，拿到退出码 child.on('close', (code) => { console.log(`退出码 ${code}`); });
exec
便捷方法
SHELL创建 Shell（bash / cmd.exe）
DATA缓冲全部输出，一次性回调
USE短时、输出量小的命令
⚠ 把用户输入直接拼进命令字符串，会带来命令注入风险
import { exec } from 'node:child_process'; // 在 Shell 中执行完整命令字符串 exec('ls -lh /usr', (error, stdout, stderr) => { if (error) return console.error(error); // 缓冲后的完整输出 console.log(stdout); });
execFile
更高效
SHELL默认不创建，更轻量高效
DATA缓冲回调（同 exec）
USE直跑可执行文件，无需管道 |、重定向 >
import { execFile } from 'node:child_process'; // 不创建 Shell，直接执行文件 execFile('bash', ['--version'], (err, stdout) => { console.log(stdout); });

// spawn 是核心——exec、execFile 等高级方法大多基于它实现

CLAUDE CODE SOURCE · TOOL CHOICE
07 / 08

Claude Code 为什么选 execFile？

源码中的命令执行工具选择了 execFile 而非 exec，这背后有多重考量

隐患 01 · EXEC
exec 会隐式创建 Shell
Windows 上默认调用 cmd.exe，其解析语义与 Bash 存在显著差异，给跨平台命令执行带来隐患。
exec('ls -la') → cmd.exe /c ... ≠ bash 语义
隐患 02 · SPAWN
spawn 需要手动拼流
stdout / stderr 是 Stream，要手动监听 data 事件、拼接 chunk、处理编码转换——繁琐且容易出错。
stdout.on('data', chunk => buf += chunk) // 繁琐
▶
execFile
源码之选
✓显式指定 Bash 解析命令——Windows / Linux / macOS 行为一致
✓底层细节全部封装——回调一次拿到完整输出字符串
✓场景匹配——输出拼成字符串返回给大模型，无需流式
execFile('bash', ['-c', cmd], (err, stdout) => { // 完整输出 → 返回给 LLM });
跨平台一致 ✓ · 代码简洁 ✓ —— execFile 是更合适的选择

Bash Shell 工具的实现

概括而言，围绕两点展开：统一的执行入口 与 跨平台的 Shell 路径定位

核心点 01 · 执行入口
统一的执行入口
为保证各操作系统下命令执行结果一致，工具统一通过系统自带的 bash 程序来运行 Shell 命令。
在 Node.js 中借助 child_process 的 execFile 方法，直接调用 bash 可执行文件，将待执行命令作为参数传入。
execFile('bash', ['-c', command])
核心点 02 · 路径定位
跨平台的 Shell 路径定位
关键在于如何在不同操作系统上准确找到 bash 程序文件的路径。
Linux系统默认路径或 which 命令查找，处理直接
Windows早期强制依赖 Git-Bash：先定位 Git 程序路径 → 反推 Git Bash 位置；失败则报错，提示必须安装 Git-Bash
