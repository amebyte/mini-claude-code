完整的调用链

从「找文件」到「改代码」，完整跑一遍

调用链 
模型: 我要改「处理登录」的代码，但不知道文件在哪
├─ 调用 Glob(pattern="**/*.ts")       # 按名字先缩小范围
│      → 返回一批 .ts 路径
├─ 调用 Grep(pattern="login", glob="*.ts")   # 按内容精确定位
│      → 返回 "auth.ts:42: function login()"
└─ 调用 Read(file_path="src/auth.ts")  # 真正读内容
→ 拿到全文，开始改代码
整个数据流，一张图看懂
数据流 
┌───────────┐
│   模型    │   "帮我找到登录逻辑的文件"
└─────┬─────┘
│ 调用工具（tool_use）
┌─────▼─────────────────────────────┐
│   Glob（按文件名）  /  Grep（按内容） │   ← 定位器，只返回候选路径
└─────┬─────────────────────────────┘
│ 返回 "src/auth.ts" / "auth.ts:42: login()"
┌─────▼─────┐
│   Read    │   ← 阅读器，返回完整内容
└─────┬─────┘
│ 返回全文
┌─────▼──────────┐
│  Edit / Write  │   ← 修改器，落盘
└────────────────┘

为什么要拆成两个？

为什么不是做一个「万能搜索工具」？

核心原因——这两种「找」的本质是正交的
Glob
回答「叫什么名字 / 长什么样」
匹配的是 文件路径字符串
所有 `.ts` 文件 · `src/**` 下面的一切
Grep
回答「里面写了什么」
匹配的是 文件内容
有个函数叫 `expandPath`
