Q&A · SSE VS WEBSOCKET
06 / 09

SSE vs WebSocket：单向 vs 双向

回答上个小节的问题 —— 两者的区别到底是什么？

SSE
单向
客户端
C → S 仅首次请求
✗ 之后不能再发
S → C 持续推送
服务器
仅第一次请求：客户端 → 服务器
之后只能：服务器 → 客户端 （客户端不能再发消息）
WebSocket
双向
客户端
C → S 随时发送
S → C 随时发送
服务器
连接建立之后
客户端、服务器随时互发消息

单向够用选 SSE（更轻，就是 HTTP）；需要双向实时，才上 WebSocket

SSE · TEXT FORMAT
07 / 09

SSE 事件的文本格式

每个事件由若干「字段: 值」行组成，事件之间用一个空行 \n\n 分隔

SSE 原始文本
字段: 值 ← 每一行的固定格式
data: {"delta":{"text":"你"}}
\n\n
data: {"delta":{"text":"好"}}
按 \n\n 切分
→
客户端切分结果
事件 1
data: {"delta":{"text":"你"}}
事件 2
data: {"delta":{"text":"好"}}

事件 = 若干「字段: 值」行，事件之间 = 一个空行 —— 客户端就是靠 \n\n 来切分事件的

SSE · EVENT STREAM
08 / 09

Claude 的 SSE 事件流：6 种事件，固定顺序

每个事件由「字段: 值」行组成，事件之间用一个空行 \n\n 分隔 —— 客户端靠它切分事件

层级数据模型
message（一条消息） └── content block 0 （比如 text 块） │ ├── delta 0 │ ├── delta 1 │ └── ... ├── content block 1 （比如 tool_use 块） │ ├── delta 0 │ └── ... └── ...
SSE 原始报文
event: message_start
data: {"message":{… content: [], usage 占位}}
\n\n 切分
event: content_block_start
data: {"content_block":{"type":"text","text":""}}
\n\n 切分
event: content_block_delta
data: {"delta":{"text":"你好"}}
data: {"delta":{"text":"，"}}
data: {"delta":{"text":"世界"}}
event: content_block_stop
data: {"index":0}
event: message_delta
data: {"delta":{"stop_reason":"end_turn"},"usage":{…}}
event: message_stop
data: {"type":"message_stop"}
6 种自定义事件 · 固定顺序
1
message_start
整条消息的骨架：content 还空着，usage 先占位
2
content_block_start
声明第一个文本块（text 为空）
3
content_block_delta
逐块吐字，delta.text 是新吐出的一小段文字
×N
4
content_block_stop
文本块结束
5
message_delta
携带 stop_reason 与最终 token 用量
6
message_stop
整条消息结束

顺序固定：message_start 开始、message_stop 结束 —— 按 \n\n 切事件，按类型拼装层级消息

EVENTSOURCE · HARD LIMITS
09 / 09

EventSource 的硬限制：想用都用不了

EventSource API 有几个硬限制，让它经常「想用都用不了」

EVENTSOURCE API · 4 条硬限制
✗
只能发 GET
不能 POST
✗
不能自定义请求头
带不了 Authorization / x-api-key
✗
不能带请求体
带不了 JSON body
✗
只存在于浏览器
Node 22 才加实验性支持
调大模型 API 恰恰需要 POST + Authorization 头 + JSON body
—— EventSource 一个都满足不了
@ANTHROPIC-AI/SDK 的做法（OPENAI 同款）
fetch 拿到流
POST + 请求头 + body 一次给齐
await fetch(url, { method: "POST", … })
▼
SSEDecoder 切块
按 \n\n 把流切成一个个事件
chunk = "data: {\"delta\":{…}}\n\n"
▼
剥掉 data: 前缀
只保留 JSON 部分
"{\"delta\":{…}}"
▼
JSON.parse
得到消息对象，交给上层拼装
{ delta: { text: "你" } } ✓

OpenAI SDK、Anthropic SDK 全是这个套路 —— 它们把「解析 SSE 文本」这件小事自己实现了
